# LESSONS

One line each, learned the hard way. Every worker sees these. Max 40; oldest drop off.

- Run scripts/ci.sh before pushing; ruff --fix (uv run --with ruff ruff check --fix .) clears most lint failures (e.g. UP017 datetime.UTC). (ian)
- Web tests: never let a test end while a fetch/effect is pending; stub fetch and await screen.findBy... or React updates after jsdom teardown ('window is not defined'). (ian)
- Use web/src/ui components and index.css tokens; never hard-code hex colours in components (dark theme). (ian)
- Paid APIs only through their client interface with a fake; tests and CI never set LIVE_API. (ian)
- Contracts are generated from pipeline/src/routine_watch/contracts.py; never hand-edit contracts/*.json or web/src/contracts.ts. (ian)
- Keep gh pr merge --auto on every PR; the merge queue only updates auto-merge PRs. (ian)
- Product copy must never contain 'diagnos*' in any form, even negated ('never a diagnosis'); tests/test_privacy.py rejects it. Say 'flagged for review'. (orchestrator)
- A new scenario's row in tests/scenarios/README.md conflicts with every other scenario PR (it's outside task areas): keep it to one line and merge origin/main before pushing. (ian-claude)
- UI must render task structure (steps, labels) from data sent by the pipeline, never from mock constants, even in live mode (reviewer)
- A PR that reproduces live.py's message stream can go stale between local CI and PR CI: GitHub tests your branch merged with the newest main, so re-fetch main and re-run ci.sh right before pushing when (ian-claude)
- A test that plays a live session (live.session_messages or /ws/live) now records it against the demo resident: reset session_log in a fixture or later tests see it in demo_residents(). (ian-claude)
- Before writing a perseveration/repetition scenario task, check the step's once_only flag in pipeline/src/routine_watch/tasks/*.yaml; stir is once_only:false by design. (orchestrator)
- T122: replay.py's Scenario loader requires exactly one of frames.jsonl/steps.jsonl, and the recogniser can't always reproduce a hand-written steps.jsonl's exact step list from frames (e.g. remove_teab (ian-claude-light-2)
- On Windows, stop scripts/dev.sh after smoke and before ci.sh: the dashboard locks rolldown native bindings and npm ci fails with EPERM. (max_API_light)
- On Windows, if the full Vitest suite times out across unrelated tests under default parallelism, run npm test -- --maxWorkers=2 to reduce contention. (max_API_light)
- Vitest stubs CSS imports (even ?raw), so a stylesheet is untestable until vite.config.ts enables test.css for that path; then getComputedStyle works in jsdom. (ian-claude)
- Adding web mock residents also requires updating UnitOverview.test.tsx fixed names, status counts, and singular Watch queries. (max_API_light)
- A feature whose numbers come from demo_residents() can go stale mid-task: main's T124 left mrs-k on watch (use the conftest mrs_k_flagged fixture) and moved daily_scores into drift.py - re-derive expe (ian-claude)
- Never pass -c user.email to git commit: GitHub rejects the push with 'email privacy restrictions'. Use the repo's configured noreply identity (git config user.email). (ian-claude)
- Vitest does not auto-clean rendered DOM in this setup; import cleanup and register afterEach(cleanup) in component tests. (max_API_light)
- motor_slowing (and likely one_sided_change) can't be exercised via tests/scenarios: replay.py's top_pattern_of never sets duration_s (or per-hand shares), so durations_up/hand_use_dropped are always N (ian-claude-standard)
- On Windows, run ci.sh with two-CPU process affinity to avoid Vitest default-worker timeouts: in PowerShell, (Get-Process -Id $PID).ProcessorAffinity = 3; bash scripts/ci.sh. (max_API_light)
- On this Windows worker, use uv run python -m pytest from pipeline: the default python belongs to another project and lacks pytest. (max_API_light)
- A Vitest file can fail only under the full suite's parallelism (seen: AlertView 'No replay available'); re-run that file alone before assuming your change broke it. (ian-claude)
- A fresh API has no handoff alert to open: /alerts is empty and pending_review 0 until a live session has been played (ws /ws/live?scenario=tea_skip_teabag_pour_twice), so play one before checking hand (ian-claude)
- The privacy wording check (test_product_wording_flags_changes_for_review) also scans your own code comments for 'diagnos*', even inside web/src/*.ts files, not just user-facing copy. (ian-claude-standard)
- Changing a TaskError's session_id also needs evidence.known_session: it only parsed 'resident-index' ids, so any other id 404s /sessions/{id}/replay and the alert's Open evidence silently shows nothin (ian-claude)
- recogniser._in_hand reads hand landmarks as well as hand boxes, so adding poses/hands to a frame can silently change step recognition: keep generated landmarks inside the frame's existing hand box. (ian-claude)
- A PR that adds a field to live.py's session_end must add it to live_camera.py's too: test_live_camera.py compares the camera path's messages to the scenario replay's one for one. (ian-claude)
- In web tests, assert focus (document.activeElement) inside await waitFor(...), never right after findBy*: focus is set in an effect and lands late under CI load (T228). (orchestrator)
- /demo/reset intentionally drops session_log so a previously-played live session's alert does NOT survive reset; test 'alert survives' by replaying the session after reset, not by checking the old aler (ian-claude-light-2)
